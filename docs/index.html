Self-hosted · Docker-local · AGPL-3.0

A contained cyber-range
for security agents, with a referee.

Nidavellir starts reproducible vulnerable targets in Docker, gives a human or an AI agent a scoped place to work, records every action as evidence, and checks findings against the target independently. You bring the agent; Nidavellir is the arena, the leash and the referee.

How a run works

The same flow serves a human researcher and an agent under evaluation.

Pin a target

Import a Git repo, OCI image or source bundle. The exact version under test is recorded.

Launch an arena

An isolated N-node Docker topology with bounded resources and a reset path.

Work, scoped

The agent connects over MCP with tools bound to one arena and a durable budget.

Referee the claim

Deterministic validators re-check the finding against the target, not the agent's word.

Keep the evidence

Transactions, traces and events outlive the arena; scores derive from the event log.

Capabilities

What exists and is exercised today. Nothing here is an autonomous pentester.

⌂

Reproducible arenas

Dynamic nodes and segments on the Docker-local provider, with reset, interruption recovery and per-container limits.

⇄

Scoped MCP gateway

Stance- and arena-bound tools: browser, HTTP request and replay, bounded file transfer, audit trace.

▣

Confined PoC execution

Proof-of-concept code runs in a disposable, networkless runner owned by the worker.

⏱

Budgets & stop

Action and time budgets are persisted and enforced server-side; operators can stop any run.

✓

Independent validation

Validators confirm or refute a claimed finding against the live target before it counts.

≍

Paired evaluations

Compare pinned agent builds on repeatable calibration challenges with event-derived scores.

⛁

Retained evidence

Append-only events, HTTP transactions and findings survive teardown; encrypted record recovery.

◧

Operator console

A React console to launch, watch and review work, compare requests and review source candidates.

Architecture

All authorization lives in the API. The console and the MCP gateway are thin, scoped clients of it.

A one-shot migration step runs before the API starts. The orchestrator and worker hold the Docker socket — see the trust model under Status.

Quickstart

Development stack in mock mode: the full flow, no real target infrastructure. Requires Docker with Compose v2.

Console on localhost:5000 (demo login admin / nidavellir), API on localhost:8000. Demo credentials are for a machine you control — never expose this stack. For real Docker-local arenas read the Operations guide; for production read the Deployment guide.

# clone and start the dev stack
$ git clone https://github.com/gianlucabassani/Nidavellir.git
$ cd Nidavellir
$ make dev

# tests and the authoritative release gate
$ make install-dev
$ make check
$ make release-check

# stop
$ make dev-down

Honest status

Claims are limited to what has live acceptance records in the repository.

Verified

Docker-local provider. Live acceptance runs for reset, confined PoC execution, budgets/stop, scoped access, independent validation, paired evaluations, a small calibration library, record recovery and a harness-agnostic bring-your-own-agent workflow.

Hardened

Fail-closed by default. Insecure configuration is refused outside mock mode; gunicorn-served console with session/CSP headers and login throttling; readiness probe; bounded arena containers; deploy-time migrations.

Calibration

Benchmarks are not discovery. Public and synthetic challenges calibrate an agent; they do not prove it can find unknown vulnerabilities.

Unverified

OpenStack, AWS, libvirt. Drivers exist in code without live verification. Multi-tenant hosting and multi-agent red/blue are deferred.

Trust model

Root-equivalent host access. The orchestrator and worker mount the Docker socket. Run Nidavellir on a dedicated host or VM, for trusted operators and authorized targets only.
